# Lite's grammar as railroad diagrams (tentative, 2026-10-21)

*Drawn from the cards as they stand, at Joseph's request, by session `014uHM6yNW767ksMmVtWt7Sn` (Fable 5.1); the PEG blocks were converted to mermaid's `railroad-peg-beta` the same day by session `016b7usvoaq7iyZwPtgrs2BD`, and the hand-drawn `flowchart LR` versions were then removed (they are in commit `0aeb9a0` if wanted). Nothing here is a ruling: every `%% OPEN` note marks a point no card settles or Joseph has reopened, and every `%% error` note marks a branch the parser refuses.*

*Notation: mermaid `railroad-peg-beta` (a beta diagram type, mermaid 11.16 and later). Each rule is `Name <- expression ;`. `/` is ordered choice, `*` `+` `?` the usual quantifiers, parentheses group, quoted strings are terminals, bare names are rules; `&e` and `!e` are lookahead (match without consuming) and `.` is any character, as in PEG. The beta parser has no character classes or counts, so a class is written as the choice it lists or as a quoted terminal in brackets (`"[set]"`), and "N or more" is spelled out. Terminals in capitals are the named characters of [[def:characters]].*

*What a railroad can't show: indentation. Nesting is decided by each line's column against the open elements (the `rule:nesting` gap), so these are the **line layer**: what one line may hold, and what a value may be. Treat `INDENT`/`DEDENT` as Python does, outside the diagrams.*

## 1. A line

```mermaid
railroad-peg-beta
title "A line"
line <- SPACE* (blank-line / block-line / prose-line) ;
%% SPACE* is the line's column. A TAB or other non-space whitespace there is an error ([[rule:column-shifting-whitespace-error]]); U+00A0 counts as a space with a default-off warning ([[rule:no-break-space-counts-as-space]]). Ordered choice: a line that is not blank and does not start with a block form is prose.
block-line <- element-line / attribute-line / comment-line / fence-opener / reserved-line-start ;
%% a line that starts with a block form ([[def:block-form]]); Joseph's proposed term, 2026-10-21 ("blockline"). Element and attribute lines recurse through their sameline (section 3); a comment line swallows its rest and its deeper lines (section 9); a fence opener's rest is an element head plus sameline, then the body runs to the closer (section 7)
reserved-line-start <- ("@" / "!") label ;
%% error: a line starting with a reference or directive spelling is reserved ([[rule:prose-line-start-reserved]]). Escaped with a leading backslash it is not a block start and falls through to prose ([[rule:line-start-escape]])
```

Which of these a line is, is decided by its first content once ([[def:element-line]]); a line deeper than an established text left edge is prose whatever it starts with ([[rule:deeper-marker-lines-are-text]]). «sameline» stays the name of the region after an element, attribute or fence opener; a comment line has none, so «block-line» (the kind of line) and «sameline» (the region) are different terms.

## 2. An element's head

```mermaid
railroad-peg-beta
title "An element's head"
element <- PIPE name? key* trait* ;
name <- label / quoted-name ;
%% OPEN: which characters a bare label may hold (the labels discussion, [[def:label]])
key <- "[" value "]" ;
%% [[rule:key-holds-a-value]]; escapes inside: \\ \[ \] ([[rule:key-escapes]]). OPEN: one key or several (`rule:keys-and-traits` gap)
trait <- SPACE* "." label ;
%% OPEN, provisional: spaces before a trait ([[rule:traits-may-follow-spaces]]); while that stands an unquoted name can't begin with "."
```

## 3. The rest of an element or attribute line (sameline)

```mermaid
railroad-peg-beta
title "Sameline"
element-line <- element sameline ;
attribute-line <- attribute sameline ;
attribute <- COLON name ;
%% its value is the next item on the line ([[rule:attribute-with-no-value-takes-next-value]]); none at all is an error ([[rule:missing-value]])
sameline <- (SPACE+ item)* (SPACE+ framed-comment)? EOL ;
item <- element / attribute / fence-opener / value ;
%% an attribute directly after an attribute with no value is the reserved nested-attribute error ([[rule:attribute-after-attribute-with-no-value]])
framed-comment <- SEMICOLON SPACE (!EOL .)* ;
%% [[rule:framed-comments]]; attaches to the nearest item (Joseph, 2026-10-20): an attribute's value on that line, or an element as its next child
```

What each item belongs to is not in the diagram: a value goes to the attribute still waiting for one, else to `$main` on an element line or stacks on an attribute line ([[rule:leftover-values]]); a bare `|name` after a finished value is a child at its column ([[rule:sameline-element-is-child]]); after an attribute waiting for a value it is that value ([[rule:element-after-attribute-with-no-value]]).

## 4. A value

```mermaid
railroad-peg-beta
title "A value"
value <- delimited-string / number / "true" / "false" / "nil" / list / angle / element / text / reserved-value ;
number <- "???" ;
%% OPEN: the frozen bare set and its spellings (`rule:bare-typing` gap); Joseph leans toward what the old parser had
list <- "[" SPACE* (value (SPACE+ value)*)? SPACE* "]" ;
%% [[rule:list-items-whitespace-separated]]. OPEN: an unquoted item's extent, nesting, embeds as items
angle <- "<" raw-interior ">" ;
%% [[rule:opaque-span-raw-text]]: matched brackets nest; escapes only \\ \< \> ([[rule:opaque-span-escapes]]); must close on its line. OPEN, reopened 2026-10-20: an interior that is exactly nil, true, false, a number or a delimited string would be a value of that kind, anything else raw
reserved-value <- "@" label / "!" label / "null" ;
%% error: reserved on an element's or attribute's line ([[rule:reserved-spellings]]); a bare null points to nil ([[rule:nil-spelling]])
```

Bare `hello` (unquoted, no embed): a one-piece «text» by the cards, a string of form bare by Joseph's 2026-10-20 sketch. OPEN, [[def:string]].

## 5. Unquoted text on a sameline, and its terminators

```mermaid
railroad-peg-beta
title "Unquoted text and what ends it"
text <- piece+ &terminator ;
%% "piece" is Joseph's word for a text's parts, kept until he says otherwise; the parts are bare strings and embeds (his 2026-10-08 "text has any number of pieces some of which are not strings")
piece <- embed / bare-string ;
embed <- inline-element / reference / inline-comment ;
inline-element <- "|{" interior "}" ;
%% OPEN: the interior is undesigned (Joseph, 2026-10-09); inside it an unquoted value also ends at "}" ([[rule:inline-element-value-end]])
reference <- "@{" raw-interior "}" ;
inline-comment <- ";{" raw-interior "}" ;
bare-string <- (escape / !(embed / terminator) .)+ ;
escape <- BACKSLASH "[set]" ;
%% OPEN: the set of attached escapes on an element's or attribute's line ([[rule:value-line-escapes]]); any other backslash would be an error
terminator <- SPACE+ &(PIPE / COLON / BACKTICK BACKTICK BACKTICK / SEMICOLON SPACE / BACKSLASH SPACE / "@" / "!") / EOL ;
%% [[rule:text-value-end]]. The spaces before a terminator are frame, not content ([[rule:space-before-text-end]]); the framed backslash is consumed ([[rule:framed-backslash-frame]]); "@" and "!" there are the reserved error. Embeds never end a text ([[rule:embeds-in-text]])
```

Note that `terminator` and `item` (section 3) are one list seen from two sides: whatever can start an item on a sameline is what ends unquoted text. One card should define that list once ([[def:text-terminator]], [[def:marker]]).

## 6. A delimited string

```mermaid
railroad-peg-beta
title "A delimited string"
delimited-string <- double-quoted-string / single-quoted-string ;
double-quoted-string <- DOUBLE-QUOTE (dq-escape / dq-char)* DOUBLE-QUOTE ;
dq-char <- !(DOUBLE-QUOTE / BACKSLASH / EOL) . ;
dq-escape <- BACKSLASH ( (BACKSLASH / DOUBLE-QUOTE / SINGLE-QUOTE / "/" / "#" / "n" / "t" / "r" / "f" / "e") / "0" !DIGIT / "x" "[0-7]" HEX / "u{" hex-run (SPACE hex-run)* "}" / "u" HEX HEX HEX HEX ) ;
%% [[rule:double-quote-escapes]]; error: any other backslash in "…"
hex-run <- HEX (HEX / "_")* ;
single-quoted-string <- SINGLE-QUOTE (sq-escape / sq-char)* SINGLE-QUOTE ;
sq-escape <- BACKSLASH (SINGLE-QUOTE / BACKSLASH) ;
sq-char <- !(SINGLE-QUOTE / EOL) . ;
%% [[rule:single-quote-escapes]]: every other backslash is literal
```

The productions are the ones drafted in [[def:delimited-string]]'s notes. A raw EOL inside either is an error ([[rule:newline-in-string-is-error]]); nothing inside is UDON syntax ([[rule:strings-like-ruby]]).

## 7. A fence

```mermaid
railroad-peg-beta
title "A fence"
fence-opener <- BACKTICK BACKTICK BACKTICK BACKTICK* element-head sameline EOL ;
%% [[rule:fence-opener-line]]: the rest of the line reads like an element's line (name = the language, keys, traits, attributes, a framed comment); no later BACKTICK on the line ([[rule:fence-label-no-backtick]]). OPEN: Joseph leans to accept TILDE fences too (2026-10-20), not carded
fence-body <- (!fence-closer line)* ;
%% never scanned ([[rule:fence-body-not-scanned]]); every line keeps its ending ([[rule:fence-body-line-endings]]); dedented by the default handler unless the trait exact ([[rule:fence-body-dedent]], [[rule:fence-exact-trait]])
fence-closer <- SPACE* "BACKTICK, as many as the opener or more" (SPACE+ framed-comment)? EOL ;
%% [[rule:fence-closes-at-n-or-more]]; error: anything else after the closer's backticks ([[rule:fence-closer-trailing-text-is-error]])
```

The opener may sit anywhere structure can start, sameline included ([[rule:fence-anywhere-structure]]). The closer's column then takes part in nesting ([[rule:fence-closer-is-a-line]]). What the default handler accepts on the opening line (keys, `.exact`, a comment) is post-lexical ([[rule:fence-default-handler]]).

## 8. A prose line

```mermaid
railroad-peg-beta
title "A prose line"
prose-line <- SPACE* BACKSLASH? (embed / escaped-embed / .)* EOL ;
%% [[rule:prose-passes-through]]: a leading backslash is consumed and sets the indent ([[rule:line-start-escape]]); everything else passes through except embeds
escaped-embed <- BACKSLASH ("|{" / "@{" / ";{") ;
%% [[rule:prose-escaped-embeds]]: the opener is literal, the backslash consumed
lone-backslash-line <- SPACE* BACKSLASH SPACE* EOL ;
%% a kept empty line of text ([[rule:lone-backslash-line]]); spaces before the backslash past the left edge are content
```

A `;`, `@name` or `!word` partway along a prose line is text; only line starts are decided differently (section 1). Consecutive prose lines under one owner form one text ([[rule:text-lines-join]]); a `;` comment line between them is a child node, a peer of the texts, so the prose on either side of it is two texts (Joseph, 2026-10-21; [[rule:comments-in-tree]]).

## 9. A comment line

```mermaid
railroad-peg-beta
title "A comment line"
comment-line <- SPACE* SEMICOLON (!EOL .)* EOL deeper-line* ;
%% [[rule:comment-blocks]], [[rule:comment-block-owns-deeper-lines]]. OPEN: a line whose first non-space characters are ";{" is a comment line by this rule, or an inline comment inside the surrounding prose by the embed rules (Joseph's own example, 2026-10-21); the agent expects the second
```

## What drawing the grammar exposed (for the cards, not decided here)

- Four productions have no body yet: `label` (characters), `number` (bare typing), the `inline-element` interior, and the nesting that places lines. Those are the gap rows plus the labels and embeds discussions.
- `terminator` and `item` are one list written twice (section 5).
- The framed comment appears in three places with one shape (sameline, fence opener's sameline, fence closer); `;{…}` in two (a text piece, and perhaps a line start). The `;{` line start is the one real ambiguity the grammar can't resolve on its own.
- Every nonterminal here is a term. The ones the tree's shape depends on are `value`, `text`, `piece`, `bare-string` and `terminator`; the rest are Joseph's words already or need only confirming.
