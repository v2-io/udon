# Lite's grammar as railroad diagrams (tentative, 2026-10-21)

*Drawn from the cards as they stand, at Joseph's request, by session `014uHM6yNW767ksMmVtWt7Sn` (Fable 5.1); the PEG blocks were converted to mermaid's `railroad-peg-beta` the same day by session `016b7usvoaq7iyZwPtgrs2BD`, and the hand-drawn `flowchart LR` versions were then removed (they are in commit `0aeb9a0` if wanted). Being revised with Joseph section by section (2026-10-21: the blank / block-line / prose split, and the `-start` rules). Nothing here is a ruling: every `%% OPEN` note marks a point no card settles or Joseph has reopened, and every `%% error` note marks a branch the parser refuses.*

*Notation: mermaid `railroad-peg-beta` (a beta diagram type, mermaid 11.16 and later). Each rule is `Name <- expression ;`. `/` is ordered choice, `*` `+` `?` the usual quantifiers, parentheses group, quoted strings are terminals, bare names are rules; `&e` and `!e` are lookahead (match without consuming) and `.` is any character, as in PEG. The beta parser has no character classes or counts, so a class is written as the choice it lists or as a quoted terminal in brackets (`"[set]"`), and "N or more" is spelled out. Terminals in capitals are the named characters of [[def:characters]].*

*What a railroad can't show: indentation. Nesting is decided by each line's column against the open elements (the `rule:nesting` gap), so these are the **line layer**: what one line may hold, and what a value may be. Treat `INDENT`/`DEDENT` as Python does, outside the diagrams.*

## 1. A line

```mermaid
railroad-peg-beta
title "A line"
line <- SPACE* (blank-line / block-line / prose-line) ;
%% SPACE* is the line's column. A TAB or other non-space whitespace there is an error ([[rule:column-shifting-whitespace-error]]); U+00A0 counts as a space with a default-off warning ([[rule:no-break-space-counts-as-space]]). Ordered choice: a line that is not blank and does not begin with a start is prose
block-line <- element-start element-head sameline / attribute-start name sameline / comment-start comment-rest / fence-start element-head sameline EOL fence-body fence-closer / reserved-start ;
%% a line that begins with a block form ([[def:block-form]]); Joseph's term, 2026-10-21. Each alternative is a start (section 2) and what that start owns: element and attribute lines own a sameline (section 4); a comment line owns its rest and its deeper lines (section 10); a fence owns a head, a sameline and a body to its closer (section 8); a reserved start is an error
```

Which of these a line is, is decided by its first content once ([[def:element-line]]); a line deeper than an established text left edge is prose whatever it starts with ([[rule:deeper-marker-lines-are-text]]). A leading `\` is not a start, so such a line falls through to prose with the backslash consumed ([[rule:line-start-escape]]). «block-line» names a kind of line; «sameline» names the region after an element, attribute or fence start, which a comment line does not have.

## 2. The starts

```mermaid
railroad-peg-beta
title "The starts: what begins a block form, and its guard"
element-start <- PIPE !"{" ;
%% OPEN: the guard. Which characters may follow | for it to open an element (the labels discussion, [[def:label]]; part 1's lean separates "does | open an element?" from "is this a valid name?"); and whether |{ at a line start is a text line or something else (embeds undesigned)
attribute-start <- COLON &name-start ;
%% OPEN: what counts as name-start (a label character or a quote), which decides whether " :-)" in sameline text opens an attribute
comment-start <- SEMICOLON !"{" ;
%% OPEN: the !"{" is the agent's expectation, not a ruling: whether a line or an item beginning ;{ is a comment or an inline comment inside text ([[rule:comment-blocks]]; Joseph's example, 2026-10-21)
fence-start <- BACKTICK BACKTICK BACKTICK BACKTICK* ;
%% N backticks, N at least 3 ([[rule:fence-opens-with-backticks]]); the line must hold no later backtick ([[rule:fence-label-no-backtick]]). OPEN: Joseph leans to accept TILDE fences too (2026-10-20), not carded
reserved-start <- ("@" / "!") &name-start ;
%% error: reserved spellings ([[rule:reserved-spellings]], [[rule:prose-line-start-reserved]]); @{ is not reserved, it is a reference (an embed)
start <- element-start / attribute-start / comment-start / fence-start / reserved-start ;
%% "start" is Joseph's word ("special starts", 2026-07-12) for what the cards call a marker with its guard ([[def:marker]], the `rule:markers` gap). The same starts begin items on a sameline (section 4) and end unquoted text (section 6)
```

## 3. An element's head

```mermaid
railroad-peg-beta
title "An element's head"
element <- element-start element-head ;
element-head <- name? key* trait* ;
name <- label / quoted-name ;
%% OPEN: which characters a bare label may hold (the labels discussion, [[def:label]]); quoted names follow the delimited-string rules ([[rule:quoted-element-and-attribute-names]])
key <- "[" value "]" ;
%% [[rule:key-holds-a-value]]; escapes inside: \\ \[ \] ([[rule:key-escapes]]). OPEN: one key or several (`rule:keys-and-traits` gap)
trait <- SPACE* "." label ;
%% OPEN, provisional: spaces before a trait ([[rule:traits-may-follow-spaces]]); while that stands an unquoted name can't begin with "."
```

## 4. The rest of an element or attribute line (sameline)

```mermaid
railroad-peg-beta
title "Sameline"
sameline <- (SPACE+ item)* (SPACE+ framed-comment)? EOL ;
item <- element / attribute-start name / fence-start element-head / value ;
%% every item but a value begins with a start (section 2). A value goes to the attribute still waiting for one, else to $main on an element line or stacks on an attribute line ([[rule:leftover-values]]); an attribute with nothing after it is an error ([[rule:missing-value]]); an attribute directly after an attribute with no value is the reserved nested-attribute error ([[rule:attribute-after-attribute-with-no-value]])
framed-comment <- comment-start SPACE (!EOL .)* ;
%% [[rule:framed-comments]]: a space on each side. It attaches to the nearest item (Joseph, 2026-10-20): an attribute's value on that line, or an element as its next child
```

Where a bare `|name` lands is not in the diagram: after a finished value it is a child at its column ([[rule:sameline-element-is-child]]); after an attribute waiting for a value it is that value ([[rule:element-after-attribute-with-no-value]]). A fence start on a sameline lands the same way ([[rule:fence-anywhere-structure]]), and its body then runs to the closer.

## 5. A value

```mermaid
railroad-peg-beta
title "A value"
value <- delimited-string / number / "true" / "false" / "nil" / list / angle / element / text / reserved-start ;
%% a reserved start as a value is the reserved error ([[rule:reserved-spellings]]); a bare null points to nil ([[rule:nil-spelling]])
number <- "???" ;
%% OPEN: the frozen bare set and its spellings (`rule:bare-typing` gap); Joseph leans toward what the old parser had
list <- "[" SPACE* (value (SPACE+ value)*)? SPACE* "]" ;
%% [[rule:list-items-whitespace-separated]]. OPEN: an unquoted item's extent, nesting, embeds as items
angle <- "<" raw-interior ">" ;
%% [[rule:opaque-span-raw-text]]: matched brackets nest; escapes only \\ \< \> ([[rule:opaque-span-escapes]]); must close on its line. OPEN, reopened 2026-10-20: an interior that is exactly nil, true, false, a number or a delimited string would be a value of that kind, anything else raw
```

Bare `hello` (unquoted, no embed): a one-piece «text» by the cards, a string of form bare by Joseph's 2026-10-20 sketch. OPEN, [[def:string]].

## 6. Unquoted text on a sameline, and what ends it

```mermaid
railroad-peg-beta
title "Unquoted text and what ends it"
text <- piece+ &text-end ;
%% "piece" is Joseph's word for a text's parts, kept until he says otherwise; the parts are bare strings and embeds (his 2026-10-08 "text has any number of pieces some of which are not strings")
piece <- embed / bare-string ;
embed <- inline-element / reference / inline-comment ;
inline-element <- "|{" interior "}" ;
%% OPEN: the interior is undesigned (Joseph, 2026-10-09); inside it an unquoted value also ends at "}" ([[rule:inline-element-value-end]])
reference <- "@{" raw-interior "}" ;
inline-comment <- ";{" raw-interior "}" ;
bare-string <- (escape / !(embed / text-end) .)+ ;
escape <- BACKSLASH "[set]" ;
%% OPEN: the set of attached escapes on an element's or attribute's line ([[rule:value-line-escapes]]); any other backslash would be an error
text-end <- SPACE+ &(start / BACKSLASH SPACE) / EOL ;
%% [[rule:text-value-end]]: unquoted text ends where a start begins after a space (a framed comment-start is SEMICOLON SPACE), at a framed backslash, or at the end of the line. The spaces before are frame, not content ([[rule:space-before-text-end]]); the framed backslash is consumed ([[rule:framed-backslash-frame]]). Embeds never end a text ([[rule:embeds-in-text]])
```

`text-end` and `item` are now one list, the starts of section 2, seen from two sides.

## 7. A delimited string

```mermaid
railroad-peg-beta
title "A delimited string"
delimited-string <- double-quoted-string / single-quoted-string ;
double-quoted-string <- DOUBLE-QUOTE (dq-escape / dq-char)* DOUBLE-QUOTE ;
dq-char <- !(DOUBLE-QUOTE / BACKSLASH / EOL) . ;
dq-escape <- BACKSLASH ( (BACKSLASH / DOUBLE-QUOTE / SINGLE-QUOTE / "/" / "#" / "n" / "t" / "r" / "f" / "e") / "0" !DIGIT / "x" "[0-7]" HEX / "u{" hex-run (SPACE hex-run)* "}" / "u" HEX HEX HEX HEX ) ;
%% [[rule:double-quote-escapes]]; error: any other backslash in "…"
hex-run <- HEX (HEX / "_")* ;
single-quoted-string <- SINGLE-QUOTE (sq-escape / sq-char)* SINGLE-QUOTE ;
sq-escape <- BACKSLASH (SINGLE-QUOTE / BACKSLASH) ;
sq-char <- !(SINGLE-QUOTE / EOL) . ;
%% [[rule:single-quote-escapes]]: every other backslash is literal
```

The productions are the ones drafted in [[def:delimited-string]]'s notes. A raw EOL inside either is an error ([[rule:newline-in-string-is-error]]); nothing inside is UDON syntax ([[rule:strings-like-ruby]]).

## 8. A fence

```mermaid
railroad-peg-beta
title "A fence"
fence <- fence-start element-head sameline EOL fence-body fence-closer ;
%% [[rule:fence-opener-line]]: after the start, the line reads like an element's line (name = the language, keys, traits, attributes, a framed comment)
fence-body <- (!fence-closer line)* ;
%% never scanned ([[rule:fence-body-not-scanned]]); every line keeps its ending ([[rule:fence-body-line-endings]]); dedented by the default handler unless the trait exact ([[rule:fence-body-dedent]], [[rule:fence-exact-trait]])
fence-closer <- SPACE* "BACKTICK, as many as the start or more" (SPACE+ framed-comment)? EOL ;
%% [[rule:fence-closes-at-n-or-more]]; error: anything else after the closer's backticks ([[rule:fence-closer-trailing-text-is-error]])
```

The start may sit anywhere structure can start, sameline included ([[rule:fence-anywhere-structure]]). The closer's column then takes part in nesting ([[rule:fence-closer-is-a-line]]). What the default handler accepts on the opening line (keys, `.exact`, a comment) is post-lexical ([[rule:fence-default-handler]]).

## 9. A prose line

```mermaid
railroad-peg-beta
title "A prose line"
prose-line <- SPACE* BACKSLASH? (embed / escaped-embed / .)* EOL ;
%% [[rule:prose-passes-through]]: a leading backslash is consumed and sets the indent ([[rule:line-start-escape]]); everything else passes through except embeds
escaped-embed <- BACKSLASH ("|{" / "@{" / ";{") ;
%% [[rule:prose-escaped-embeds]]: the opener is literal, the backslash consumed
lone-backslash-line <- SPACE* BACKSLASH SPACE* EOL ;
%% a kept empty line of text ([[rule:lone-backslash-line]]); spaces before the backslash past the left edge are content
```

A `;`, `@name` or `!word` partway along a prose line is text; only starts at the line's first content are decided differently (sections 1 and 2). Consecutive prose lines under one owner form one text ([[rule:text-lines-join]]); a comment line between them is a child node, a peer of the texts, so the prose on either side of it is two texts (Joseph, 2026-10-21; [[rule:comments-in-tree]]).

## 10. A comment line

```mermaid
railroad-peg-beta
title "A comment line"
comment-line <- comment-start comment-rest ;
comment-rest <- (!EOL .)* EOL deeper-line* ;
%% [[rule:comment-blocks]], [[rule:comment-block-owns-deeper-lines]]: everything deeper than the semicolon's column is the comment's, unparsed. OPEN: whether the space after the semicolon is content
```

## What drawing the grammar exposed (for the cards, not decided here)

- Four productions have no body yet: `label` (characters), `number` (bare typing), the `inline-element` interior, and the nesting that places lines. Those are the gap rows plus the labels and embeds discussions.
- The starts (section 2) are the `rule:markers` gap written out, and every guard in them is open except the fence's. Each is a one-line decision once the labels discussion lands.
- The framed comment appears in three places with one shape (sameline, a fence's sameline, the fence closer); `;{…}` in two (a text piece, and perhaps a line or item start). Whether `comment-start` excludes `{` is the one choice the grammar can't make on its own.
- Every nonterminal here is a term. The ones the tree's shape depends on are `value`, `text`, `piece`, `bare-string`, `start` and `text-end`; the rest are Joseph's words already or need only confirming. "start" (his) would replace "marker" (agents') in [[def:marker]]; "text-end" here is a placeholder for whatever replaces the agents' "text-terminator" ([[def:text-terminator]]).
