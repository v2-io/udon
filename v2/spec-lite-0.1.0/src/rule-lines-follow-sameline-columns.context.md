# Context: [[rule:lines-follow-sameline-columns]]

*History and provenance for the card beside it. Not spec text and not a record; nothing here binds.*

- **The pitfall, raised 2026-10-29** by a fresh agent comparing KDL v2 with lite (`.int/kdl-vs-lite-2026-10-29.md`, its silent-miss table): "a sameline child misaligned by one column … silent: a different parent", which it called the lite miss it would worry about most for agents, since KDL's braces can't have it.
- **Joseph's weighting, 2026-10-29** (session `01Hgdj3fobqBFEmAFmJi6Zup`), after an example (`|td A2` at column 12 under `|table |tr |td A1`): "Ah, so if the td is indented further than earlier td's. Yes, true. A problem with python also,." Then: "Most agentic indentation issues hope to be factored away by the agentic tooling, where the intent is to insert/modify/delete via logical path without specifying indents for most things. For continuous writing/generation in the first place, I haven't seen agents mess up indentation in years at this point-- even the smallest models. And then schemas would prevent, for example, `|td |td` without an error-- leaving just the cases where you actually do have a node-type that can be recursive-- in which case the user is obviously just going to have to be extra careful.  So yes, it's a potential pitfall, but it's not particularly high on the practical worries, IMO"
- **A note the coordinator added at the time:** Python refuses an indented line nothing opened ("unexpected indent"), so its silent indentation mistakes are mostly dedents; lite allows indenting under any element, so the rightward slip is the silent one. A warning for it was floated and not pursued, on Joseph's weighting above. Related unwritten card: siblings at inconsistent columns (the `rule:nesting` gap).
