# Context: [[rule:unquoted-run-is-one-value]]

*History and provenance for the card beside it. Not spec text and not a record; nothing here binds.*

- **Where it came from.** The de novo audit of the PEG (`.int/peg-audit-2026-10-21.md` §4.1) showed that Joseph's 2026-10-21 lean (a sameline attribute takes one value) together with typing by spelling gives `|book :title 1984 is a novel` → `title 1984`, `$main ‹is a novel›`. The session agent proposed, 2026-10-21: "An unquoted run on a line is one value. It is typed by its spelling only when the whole run spells a number, true, false or nil; otherwise the whole run is a text."
- **Joseph's restatement, 2026-10-21** (`.int/STEWARD-VERBATIM.md`): "when expecting a value and there is no explicit delimeter (whether <...> or '...' or "..." etc...) -- scan until one of the block-start sequences and then parse that as the value and close the attribute. Does that sound like it?" The agent confirmed it, with precisions: what ends the scan (a start after a space, the framed backslash, end of line; embeds are inside); closing the attribute is automatic for a run and a separate lean for self-ending values. Written up as a provisional card and reviewed for impact (`.int/impact-unquoted-run-2026-10-21.md`).
- **Three options contrasted, 2026-10-21.** (A) the first character commits (a digit starts a number; `920px` an error). (B) the whole run decides (`8080` a number, `920px` a text): the card's first Statement. (C) Joseph's branch "always text except typed": bare is text, `<…>` types with commit/error inside.
  - His words on A: "If it was a programming language instead of a notation I would be happy saying digit (and -/+ etc.) commit to numeric and error if it encounters something like 920-lumens-- but in notation there are units all the time-- 920px  920MB, etc."
  - His words on B, against the streaming budget ("udon could stream / parse a document with no more than ~4 character lookahead (and between 0-1 lookahead for the vast majority of udon)"), with `4938422…2412124p`: "if the streaming parser is forced to buffer essentially unlimited amount of the incoming stream before being able to output any partial text or partial node etc., the architecture has to change quite a bit, and there is room for DoS type attacks and buffer overflows etc." The session agent (`017CGtyM`) had claimed B needs no more lookahead than the text-end guard; that was wrong, since a number's length is unbounded. The same objection decided C's open bit: a bare run spelling a primitive is not typed.
  - His C, as given: `|p :held <nil>`, `|q :hold <901.2>`, `|r :some 9 - 13>2? yes?.... ; finally ended the text...`, `|s :more-text <"this is \n\t\t something else altogether-- required \" or ' even though inside the <> in order to be explicitly typed">`, `|t :wow <uint32|0x992BC> ; error- reserved for now-- only allow bare nil, booleans, numeric in all their compexity (see the older udon numeric syntax) (now we *can* commit/error) and an explicit text delimiter.`
- **The lean, 2026-10-21.** The agent offered C plus a view that reads a bare text spelling exactly a primitive as that primitive. Joseph: "I like that a lot-- go ahead and record that as my current lean-- C with the view. I agree 920px being an error violates least surprisal, <920px> error I can understand, 8080 being text that I haven't turned into a number yet and in this case don't intend to because I use it passed along as text instead of for it's mathematical value, is definitely ok to me surprisal-wise-- with my "ensure the ports add up to less than 1million" imaginary function doing just fine either way."
- **Earlier words that bear on it.** 2026-10-09 (on value-line escapes): escaping "what would otherwise be a type differentiator (number, quote, <, etc.)" so that it "starts some text instead"; 2025-12-31: "one of the main differentiators for UDON is the fact that it parses values instead of string+value-peeking like yaml has always done"; the 2026-07-28 teaching rule "just pretend the same-line part has each of its parts on consecutive new lines".
- **Gotcha he called expected (2026-10-21)**, written for B: `:width 7 ;{px}` a text, `:height 7 ; px` a number. Under the lean both are texts in the tree, and the view keeps the difference.
