# Context: [[rule:unquoted-run-is-one-value]]

*History and provenance for the card beside it. Not spec text and not a record; nothing here binds.*

- **Where it came from.** The de novo audit of the PEG (`.int/peg-audit-2026-10-21.md` §4.1) showed that Joseph's 2026-10-21 lean (a sameline attribute takes one value) together with typing by spelling gives `|book :title 1984 is a novel` → `title 1984`, `$main ‹is a novel›`. The session agent proposed, 2026-10-21: "An unquoted run on a line is one value. It is typed by its spelling only when the whole run spells a number, true, false or nil; otherwise the whole run is a text."
- **Joseph's restatement, 2026-10-21** (`.int/STEWARD-VERBATIM.md`): "when expecting a value and there is no explicit delimeter (whether <...> or '...' or "..." etc...) -- scan until one of the block-start sequences and then parse that as the value and close the attribute. Does that sound like it?" The agent confirmed it, with three precisions now in the Statement: what ends the scan (a start after a space, the framed backslash, end of line; embeds are inside); the run is one value, typed only if the whole run spells a primitive; closing the attribute is automatic for a run and is a separate lean for self-ending values.
- **His instruction:** "write it up as a card and have a fresh agent look for any inconsistencies between that rule and everything else including verbatim statements and leans etc.-- in order for us to know what the impact radius is." So `strength: provisional`, `awaiting-decision: true`.
- **Earlier words that bear on it.** 2026-10-09 (on value-line escapes): escaping "what would otherwise be a type differentiator (number, quote, <, etc.)" so that it "starts some text instead"; the 2026-10-08 ruling that sameline text "ends with a *block* form of ;, |, or :"; the 2026-07-28 teaching rule "just pretend the same-line part has each of its parts on consecutive new lines".
