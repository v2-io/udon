## ⚠ Needs Joseph's immediate attention (each is a decision, not a detail)

1. **The node-vs-flow non-equivalence silently collapses.** SEMANTICS §4 rules `:x |em hi` ≢ `:x |{em hi}` — today the second is a flow value. Under the R4 overturn at the clean slot, `:x |{em hi}` binds the inline element *as the value* — and in the model an inline element is an Element. Unless inline-ness becomes model-visible, the two spellings become **model-identical**, silently overturning a ruled non-equivalence. Three options, none free: (a) accept the collapse (then §6.8's "drop the braces to bind" teaching dissolves — braces and no-braces both bind at the slot, differing only mid-flow); (b) mark inline-ness on the Element node — which collides with principle 6, "sugar is designated attributes, never parallel model fields," unless inline-ness is carried as a designated attribute (`$inline?` — ugly, but at least honest); (c) keep inline-element-at-clean-slot as a one-segment flow (i.e. exempt `|{…}` from the overturn, overturning only for scalars) — which guts the `|el |{a} |{b}` sibling-stacking motivation. My lean: (a), stated loudly as its own Overturns row — the distinction was always a spelling distinction wearing a semantic costume, and the new model says so honestly. But it must be *chosen*.

2. **Every sameline inline element stops being a child of its element.** Today `|p some |{em x} text` makes `em` a child of `p`, sibling to the text segments (§5.6). Under $main, the whole tail is a flow *value* of `$main`, and inline forms inside a flow value are segments of the value, not children of the element (exactly as in `:n value |{em x}` today). Consumers, paths, and render pipelines that walk `content` for inline structure will find it empty and the structure relocated inside an attribute. The host `first_is_main` re-injection flag mitigates for ASTs, but the *model* answer must be explicit — this is the single largest consumer-facing consequence of $main and the capture doc doesn't state it.

3. **The text law does not survive $main unamended — and the dialogue idiom is the concrete break.** MODEL §6 reconstructs "the document's text material" from Texts + flow text segments. Two problems: (i) *Pre-existing seam the proposal makes acute:* the law never says whether **attribute** flow values count as document text material. If they do, `:title My Title` injects into reconstruction (absurd); if they don't, the sameline tail — which today is unambiguously content Text, terminator included (Appendix C vignette 1: `Text "Joined 2025.\n"`) — **drops out of text reconstruction** the moment it becomes an attribute value. Either way the law needs a rewrite naming `$main` as text-bearing — at which point $main is special-cased in the text law and is *not* "just an ordinary designated attribute"; the parallel machinery principle 6 exiled returns through the model's most load-bearing invariant. I think that price is payable (identity's `$key` is already special to references), but it should be paid knowingly. (ii) *The stitch rule is not optional:* `|element "hello," she said` yields a stacked $main of String + flow. Pure concatenation gives `hello,she said` — the separator space was a separator, not content. The virtual-line theory itself supplies the principled answer — **each stacked $main value is a virtual line; join with `\n`** — but then the dialogue idiom reconstructs as `"hello,"⏎she said`, not the single line the author wrote. Terminator ownership (does $main carry the tail's `\n`?), the stitch join, and the BlankLine seam (a blank between tail and block prose was *interior to text*; under $main it sits at the attribute/content boundary and flips to ornamentation) all need one coherent ruling. This is pin 3, but it is not "core guidance vs host" — it is the text law's definition.

4. **The `\`-operator's scope must be pinned or the escape's own law breaks.** §4 rules `\` "anywhere else — a literal backslash," and mid-flow literalness is what keeps `C:\Users\me` safe with *no framing analysis at all*. The pseudo-LF operator, read generally, gives a **framed** mid-flow `\` breakout semantics — a fourth position row for the one escape, retyping every document with a framed backslash in prose (rare, not zero: LaTeX fragments, "either \ or" styling). ESC-BREAKOUT's history says the breakout demand is real *for sameline attribute flows specifically*. Recommendation: pin the operator to **the Line Scan / sameline value space only** — a framed `\` there is a pseudo-LF (deriving ESC-BREAKOUT, as the capture doc hopes); in committed block prose and in `\`-forced text, `\` stays literal, §4 untouched. Without this pin, the elegant general reading silently amends §4, and the doc's "framed `\` mid-line … exactly what a real Structure-Position `\` does" sentence *is* the general reading.

## 1. Is "clean value-expected position" crisply definable? Per-context walk

The overturn's trigger — "no flow committed, no token started" — is the same state §6.4 already tracks, so it is *definable*. But it occurs in **seven** places now, and the overturn cannot be uniform across them without colliding with K7 and K8. It needs a context table, not a phrase:

| Context | Clean slot exists? | Overturn should apply? | Why |
|---|---|---|---|
| Element sameline slot ($main) | yes | **yes** — this is the motivating case | `\|el \|{a} \|{b}` stacking |
| Attribute value, sameline (`:n \|{em x}`) | yes | **yes** (the flipped ruled example — see §2) | uniform value grammar |
| Inline-element interior (`\|{a \|{b}}`) | yes | already nests inline forms; the *space-is-separator* change applies | but see §2, the §5.6 sentence |
| List item | yes | **needs a call** — `[\|{a} \|{b}]` would become a list of elements, a brand-new capability nobody asked for; today the braces are just bytes in bare tokens | recommend **no**: keep list items scalar-only (existing "no flow values in a list" posture); one sentence |
| Identity bracket (K8) | yes | **no — K8 just excluded structure from the interior** (fail-safe rationale: an unclosed bracket must not swallow structure). K8's "inline forms literal or excluded" must harden to *excluded from the overturn* or K8 is silently amended hours after ratification | one sentence citing K8 |
| K7 first-deferred-line | yes | **needs a call, and it's the sharpest** — see below | |
| Flag-key position (after `:a?`) | flag rule 2 re-owns | material re-owned by the scan lands at the *element's* clean slot → $main. Reword rule 2's "never the flag's body" to name $main | mechanical |

**The K7 coupling.** K7 made the first deferred line a value position "applying §6.4/§6.5 verbatim." The overturn edits §6.4 at clean slots — so K7 inherits it *automatically*: a deferred prose body whose first line opens with an inline form (`|{em Really} — the point is…`) would type the `|{em}` as a value item instead of committing prose, and the tail of that first line lands in an undefined slot (further stacked item? content? — nothing rules it). K7 was safe against per-line surprise precisely because flow-commit swallowed everything after the first token; the overturn re-opens a fork at K7's one special position. Recommendation: **the overturn does not apply at the K7 position** — deferred first lines keep today's rule (inline braces commit flow). Asymmetric, but the asymmetry is honest: the sameline slot is a *scan* position (more structure may follow on the line, so self-delimiting values earn their keep); a deferred first line has no continuing scan, so there is nothing for a self-delimiting value to return *to* — the mid-flow/clean distinction does no work there. That rationale is checkable, not taste, and it keeps K7's ruling stable.

## 2. Which ruled examples flip (the requested inventory)

- **CORE §6.4 (in the ruled inline-brace block):** `|el :n |{em x}` — "n = flow value whose sole segment is inline em" → becomes n = the inline element as value. **Flips.**
- **CORE §6.4:** `|el :n value |{em x} :a 1` — flow had committed; **stands** (capture doc is right).
- **CORE §6.8:** "Block form binds; brace form is text… *Drop the braces to bind… keep them to inline it as text*" — the sentence and its teaching **flip at the clean slot**, survive mid-flow. Needs the three-way rewording (node-value / inline-value / flow) the capture doc anticipates.
- **SEMANTICS §4:** `|el :x |em hi` ≢ `|el :x |{em hi}` — **collapses** unless inline-ness is model-visible (urgent flag 1).
- **CORE §5.6:** "Intervening text between sibling inline forms — including a single space — is real content (round-trip fidelity)" — **flips at the clean slot** (space becomes separator); stands mid-flow. Note this sentence was itself ruled *for* round-trip fidelity; the overturn's answer must say where fidelity now lives (the stitch rule, urgent flag 3).
- **CORE §5.6:** "An inline element is a child of its containing element" — **flips for all sameline inline forms** (urgent flag 2), sameline; block-prose inline forms remain flow segments of content Text as today.
- **CORE §9 + MODEL §2:** whole-value `!{{x}}` as "one-segment flow degenerate" → becomes an Interpolation value proper at clean slots; and `|el !{{x}}` sameline becomes $main = Interpolation rather than prose-whose-sole-segment. **Flips — but see S1: this one flips from inconsistent to consistent.**
- **CORE §6.9 late-`:` example** (`|el :a 1 and a tail` ⏎ `:b 2` → WARN, text): the tail no longer opens content phase ($main-only elements never leave attribute mode), so `:b 2` becomes a **real attribute, silently** — the ruled Warning example inverts to legal. This is the intended interleave fix, but it belongs in the Overturns section next to R4's, and `AttributeAfterChildren` (Appendix B) survives only for the after-*block*-content case.
- **Appendix C vignette 1:** `|user[jw].admin :active? Joined 2025.` — content `Text "Joined 2025.\n"` → `$main` assignment; the vignette's expected Document changes. (Fixture-visible; also the terminator-ownership test case for urgent flag 3.)
- **SEMANTICS §4 last example** (`|el :a 1 tail` ⏎ `:b 2` vs `|el :a 1 :b 2` ⏎ `tail`): still non-equivalent, but for entirely new reasons ($main vs content, no warning) — rewrite, don't delete.

**And one new non-equivalence with tooling teeth:** sameline ≢ vertical *for text* means a serializer or formatter that moves a tail to the next line (or joins a first block line up) now **changes the model** — that move today is ownership-hazardous only in the warned-extension case; under $main it is *always* a semantic edit. SEMANTICS §3's forbidden-silent-changes list gains a row ("MUST NOT move text between $main and content"), and every house-style normalizer, md-press-style rewrapper, and "reflow long lines" editor action loses a degree of freedom. The accepted-price note in the capture doc covers authors; this is the *tooling* half of the price, unstated.

## 4. The pins, answered

1. **Stacked vs one-list canonical: stacked.** Confirmed hard — SEMANTICS §2.4 non-collapse forces a named substrate, and stacking is the only one where `|el "a" |child` and `|el "a" "b" |child` don't force retroactive list mutation mid-scan. Array stays a view. Note the stack is always contiguous (nothing can interleave a child between two sameline $mains — after a block form opens, the line belongs to it), which is what keeps the stitch rule simple.
2. **Name:** `$text` is wrong (the slot holds typed values); `$tail` names the syntax, not the meaning, and will read as a lie in longhand block form; `$label` is a schema-flavored guess about usage. `$main` is the right kind of neutral. Half-alternative worth ten seconds: `$` alone (the empty designated name — "the default attribute"), maximally short for the most common attribute in the language and visually distinct in longhand (`:'$'`); if paths will type this forever, shortest-correct has value. Either is defensible; decide by paths ergonomics.
3. **Stitch rule:** not host territory — it's the text law (urgent flag 3). Lean: virtual-line join (`\n` between stacked $main values, $main stream before content stream), because it's the reading the operator model itself derives; accept the dialogue-idiom consequence explicitly or exempt flow-after-typed-value from the newline (uglier, saves the idiom).
4. **R4 wording + flips:** §2 above is the inventory; the wording should be scoped by the §1 context table, not by the phrase "clean value-expected position" alone.
5. **Warned-accept tier for genuinely-late attributes: not needed.** $main removes the common case; the after-real-block-content case keeps §6.9's existing Warning+text behavior unchanged (no new tier, no new machinery). The streaming late-`$key` carve is real but is a *wire* ordering question (assembly can hold `$key` open until content phase) — park it with W-work, not in K9.
6. **ESC-BREAKOUT:** dissolves into the operator **only if** the operator is scope-pinned per urgent flag 4. Pinned to the Line Scan, it exactly grants the historical `\|e :a x y \ z` breakout demand (mid-flow, sameline) without touching `C:\Users` or block prose. Unpinned, it's a bigger overturn than R4's. Don't close the OPEN row until the pin is worded.

## 5. Sideways findings

- **S1 (in the proposal's favor — current spec is internally inconsistent):** CORE §6.3's value-kind table lists Interpolation `!{{…}}` as its own value kind, while §9 rules whole-value `!{{x}}` "the one-segment degenerate" of a flow value "(a consequence of the inline-brace principle)." Both are ruled text; they disagree about the model shape of `:x !{{e}}`. The R4-overturn-at-clean-slot resolves this in §6.3's favor (Interpolation value proper; flow only when mixed). Whatever happens to K9, this contradiction exists today and wants a one-line ruling.
- **S2:** `@` at the element's clean slot: `|el @ref` is today the element's reference *child* (§6.3: "`@` and `|` behave identically here"). The operator model keeps it a child (block-form marker = pseudo-LF), which means the $main slot's value grammar **excludes `@`** while attribute slots include it. Correct, but it's an asymmetry in "one value grammar" — one sentence in the context table.
- **S3:** the capture doc's `first_is_main: false` host flag is a *projection*, and SEMANTICS §3's forbidden-changes machinery should name it: a host that re-injects $main as first child and then serializes from the AST has silently performed the exact text-migration §2's new forbidden row prohibits. The flag is fine for reading; round-trip tooling must serialize from the substrate. (Same shape as MODEL §3.2's existing ergonomic-views warning — cite it, don't reinvent it.)
- **S4:** Appendix B inventory: `AttributeValueExtendedByTrailingText` semantics shift for `:'$main'` written block-longhand (a collector line), and the K3 no-warning-for-stacking temperament suggests reviewing whether the block-line trailing-text Warning stays coherent when the same material sameline is warning-free $main stacking. Not urgent; densification-pass item.
