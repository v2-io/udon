Every feature the dialect research found, across ten dialects plus a column for Obsidian with its community plugins. Select a cell for its note. Hatched cells are ones the research did not establish, which is different from "unsupported". Rows that come only from Obsidian plugins were not researched for the other dialects, so those cells are hatched.

Core is the dialect's base definition (its spec, or its primary docs where there is no spec). Extension is a named option or plugin that is off by default. De facto is behavior a platform renders that no spec writes down. Workaround means there is no Markdown syntax for the feature and the cell shows the usual fallback, mostly raw HTML. Removed marks a CommonMark feature the dialect deliberately drops. A Core cell with no syntax of its own uses the row's example as written. Renderers that only draw a fenced code block (charts, queries, buttons, diagrams) are left out.

Sources: reports/Markdown dialect comparison.md and the research notes it cites, in udon v2/spikes/more-markdown/. Cells marked "prior knowledge" in their note were not re-verified. Most cross-dialect readings come from each dialect's written rules; about 75 inputs were run through real parsers.
