### #4 — Path language: document-scoped boundary

The day-in-the-life scenarios corpus ([[I2-scenarios-witness]]) includes a
scenario (`cross-document-seam` in [[01-understanding.scenarios]]) where an
agent following a reference hits the edge of the document: the referenced
material lives in *another file*. The corpus's journeys consistently treat
the path language as addressing **within one document only** — cross-document
hops are the *tool orchestration layer's* job (open the other file, path
within it), not the path syntax's. Its stance: that's probably right ("votes
boundary"), **but** it wants the decision made explicitly — "say so out
loud" — because if document-scope is only an accident of v1, tools will
build workflows atop it that a later cross-document path syntax would break
(and conversely, ruling it permanent frees path design from URI-style
complexity forever). The call: is document-scope a **v1 scope choice**
(revisitable, so tools shouldn't over-commit) or a **permanent boundary**
(ratifiable now, simplifying path design)? It interacts with S3
(multiple-keys/@ resolution) and the paths adjudication packet.
