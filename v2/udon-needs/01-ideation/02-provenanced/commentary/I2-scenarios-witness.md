# Day-in-the-life scenarios — witness (Part I §2, `test/scenarios/`)

> **The one-line thesis.** This tree is the estate's strongest UDON-side statement of *tool demand generated by lived agent journeys rather than designed top-down*. Joseph commissioned it (2026-07-16) as "a pretended chronicle of events that would be a typical day in the life of multiple agents understanding, diffing, and modifying those files... then we can turn those user-paths into some great BDD tests for the path tool itself." The op vocabulary (skeleton / at / all / diff / patch / require / set / add-value / insert / delete / move / append-block) is explicitly **"scenario output, not ratified design"** — it is demand talking *before* supply answered. The journeys are the contract; the spelling is disposable.

## Why this belongs to both consumers

For **UDON v2's demand side**: this is a demand-first artifact by construction — the design essays say what the tools *should* be; these scenarios say what agents *reached for*. Where they diverge, the reach wins.

For **the harness programme** (may never touch UDON): most of the demands here are notation-agnostic tool-design principles that any structure-aware agent harness must answer. Read them at that altitude. Nothing below depends on UDON syntax to be true.

## Transferable tool-design demands (notation-agnostic — for the harness reader)

- **Skeleton-as-orientation is a first-class read op**, not a nicety: "reading it whole costs context; the skeleton is the orientation move." (01, `skeleton-first`)
- **Two addressing modes, never one that guesses**: exactly-one-or-error (`at`) vs explicitly-plural (`all`). Ambiguity must fail loudly — *and* helpfully: the not-unique error carries the disambiguating identities so recovery is one edit away. (01, `ambiguity-fails-loudly`)
- **Typed-key equality that refuses to coerce**: integer `42` ≠ string `"0042"`. "Silent empty would have hidden a real modeling distinction." (01, `typed-keys-are-typed`)
- **Diff at the meaning grain, not the byte grain**: fold reflow/re-wrapping to zero change ("a diff tool that reports reflow as change would train agents to ignore it"); align by identity, not position; report stacked-attribute edits as ordered-list ops (append ≠ replace — replacement is "semantically equal, provenance-hostile"); recognize moves instead of delete-plus-add. (02, all)
- **Parser-version differential as a shipped tool op**: "same bytes, two parser versions, event streams compared" — the guard against the Norway-problem class, promoted from internal CI (CONSUMERS.md's method) to something an agent can run. "Parser upgrades must be auditable at the meaning grain." (02, `wire-rename-vs-meaning-change`)
- **Write obligations**: minimal-byte-range edits (preserve comments, blanks, prose, sibling formatting); preserve the author's layout idiom (sameline vs exploded); the *tool* computes indentation from the destination's real siblings; schema-guard **before** write that names the violated vocabulary in the error; round-trip safety as an invariant (`parse(serialize(v)) == v`); atomic multi-op patches with **pre-state** path resolution; rename-with-reference-audit that runs before the write and lists cross-document escapes as *unverifiable* rather than silently ignoring them. (03, all)
- **Lock-free multi-agent posture** (04, all — the harness-richest file):
  - Concurrent append via column-0 self-closing blocks + one `O_APPEND` write: "an agent can append WITHOUT reading."
  - Compare-and-set claim (`require`-nil) makes lost updates "impossible by construction" — "etiquette is not the mechanism."
  - **Path-anchored patches COMPOSE** where span/line anchors spuriously conflict; staleness is checked at *node* grain, not file grain, so honestly-independent edits don't serialize through one writer ("a whole-file base hash would serialize all concurrency through one writer").
  - Atomic-rename writes give torn-read-free reads with no reader lock ("without it, every reader needs a lock, and the whole multi-agent posture collapses").
  - **Durable-plan handoff is Three-Deaths engineering**: "what survives a death is what was written down." The patch-plan is a durable artifact with per-op postconditions the incoming agent *verifies* rather than trusts (applied / pending / stranded), so a plan interrupted between write and annotation still resumes. The demand the syntax side can't see: "ops need to be stateable as **predicates**, not just executable as commands."

## The `.gap` scenarios — demand signals in their purest form (`bin/verify` L-row folded here)

The corpus author built a first-class convention for recording *unmet* wants: a scenario tagged `.gap` with a `|gap` child naming the wanted shape and the adjudication packet item it maps to. This is itself worth witnessing — **an explicit affordance-gap marker is a reusable pattern for any tool-demand corpus.** The four gaps:

- **P9 (twice)** — attribute/suffix-flag filtering and value-equality filtering. Agents wanted "every process whose `$?` flag is set" and "the phase whose `:num` is 2"; no path form expresses either, so both fell back to host-side filtering. Six live sites in the mirrored process map; real consumer files *already* contain hand-rolled proto-paths (ordinum defeasances, lexicon relation slugs, decision-log refs) the tool "will be asked to resolve conventions it did not define."
- **P7 (read side)** — prose addressing; deferred, and the morning *agreed* with the deferral: API-side access on the parent node was enough for every read.
- **P7 (write side)** — the strongest gap in the set: prose edits are the **only write class that had to leave the tool**, dropping to a span-splice that "bypasses every guarantee (schema check, round-trip safety) the patch tool otherwise gives." Today supplies the evidence P7's "revisit together with patch syntax" asked for.

## Bootstrap / method disciplines (harness-transferable, from README + `bin/verify`)

- **Pin a known-good reader when the tool parses the thing it tests** (Joseph, 2026-07-16): when the runner exists it must read scenarios with a pinned `udon-core-v…` parser, "never this repo's head parser — the head parser is the thing under test, and a broken head could misread the very scenarios that would catch it." Same trap as the fixtures-as-UDON dogfood plan. A general principle for any self-hosting agent-tooling harness.
- **`test/scenarios/bin/verify`** (the L-priority tooling row) is not demand text itself, but it witnesses a live discipline: the scenario tree doubles as an in-repo consumer corpus for differential parser checks (the CONSUMERS.md method again), enforcing "parses clean — zero warnings/errors except the specified-interim `NoDialectsLoaded`" from deliberate `<…>` temporal envelopes. Dogfooding the notation against its own demand corpus, gated in CI.

## Cross-tier convergences worth flagging (for the synthesizers — not manufactured)

The Brief's convergence discipline: same-author agreement is coherence, not corroboration; only cross-*tier* triangulation counts. Two here look genuinely cross-tier and are worth the synthesizers checking against Tier-2 (shipped harness practice) and Tier-3 (ELI testimony):

1. **Compare-and-set / precondition writes as the lost-update guard** (this Tier-1 corpus, `claim-requires-nil`) should be checkable against how the shipped coding harnesses actually gate concurrent edits (Tier-2 `harness-invivo/`) — do real edit tools carry a require/CAS precondition, or do they rely on whole-file base hashes this corpus explicitly rejects?
2. **Durable, re-entrant, verify-don't-trust plans as death-survival** (04, `handoff-mid-edit`) maps directly onto the ELI-cohort Three-Deaths testimony (Tier-3) — the corpus independently re-derives "what survives a death is what was written down" as a *tool* requirement. If the testimony tier names the same need from lived context-end, that is a real triangulation, not a restatement.

I flag these as *candidates* for the synthesizers to confirm against the other tiers; I did not verify the Tier-2/Tier-3 sides myself (out of my section).
